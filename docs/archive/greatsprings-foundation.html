THE FOUNDATION

Greatsprings \u2014 Goodsprings Reimagined. The canonical spine specification. Everything is built on this; nothing contradicts it.

A grounded improv author,
not a creative god.
Consistent consequence,
not infinite content.
This is the constitution. Every feature, every decision, every line of code is tested against it.
If a thing needs the god, it is out. If it produces a consequence the world remembers, it is in.

The Articles

I \u2014 One Truth, One Door. There is a single state tree and a single mutation path. Nothing changes the world except an effect passed through applyEffect. No system reaches around it.
II \u2014 The DM Narrates and Proposes; It Never Adjudicates. The model may emit prose, classifications, and proposals. It may never set a number. Time, regard, XP, conditions, and all consequences are engine-owned. A model that tries to adjudicate is filtered at the door.
III \u2014 Grounded Author, Not God. The DM may only propose content assembled from assets, cast, and lore that already exist. Every proposal passes canon + schema + lore validation before it commits. A rejected proposal never reaches the player.
IV \u2014 Consistent Consequence, Not Infinite Content. "Account for any choice" means the world stays valid and consequential for any action \u2014 not that every action manufactures a new quest. A remembered wasteland is a correct outcome.
V \u2014 Severance Over Deletion. A node is never deleted. It is severed: its state set, its consequences run, its history written, the node kept. The world's memory is never a gap.
VI \u2014 Canon Is Write-Only to the Simulation. The sim writes history it never reads. Only the narrator reads canon. Canon is never contradicted.
VII \u2014 Determinism Is Law. Truth is the state tree; prose is a disposable view. All randomness seeds from state; iteration order is fixed; no wall-clock in logic. AI output is frozen to concrete effects at commit-time. Replay re-runs the log, never the model.
VIII \u2014 The ID Is Geography, Not Politics. {type}.{region}.{uid}, frozen. Goodsprings is gs even when the Legion renames it.
IX \u2014 Scope Is Law. 13 NPCs, one town, simulation-first. Combat is deferred. The dangling-reference backlog is the scope boundary \u2014 three open at most.

0Settled Scope

These are no longer open questions. They were decided in the grilling and they anchor everything below. Re-opening one is a foundation change, not a feature tweak.

Goodsprings, reimagined \u2014 one town 13 primary NPCs Simulation-first Immersive sim + emergent quests are the point Combat exists, but deferred The world lives and breathes off-screen Clean-room V20 spine

The roadmap (text/AI-DM \u2192 full town \u2192 2D \u2192 3D) is a fidelity ladder, not a world-size ladder. The world size is fixed at one town. That is the single most important constraint in this document, because it is what turns "account for anything" from a fantasy into a finite, solvable problem: thirteen people in one place, simulated deeply enough to react to any input.

1The Layered Architecture

Greatsprings is a deterministic spine carrying immersive-sim flesh, read by an AI narrator, grown by a validated content layer. The 61-system map is the live inventory; this is the load order.

  1. The Spine \u2014 state tree, applyEffect, registry, ID convention, hooks, turn loop, seeded RNG, save/replay. Deterministic. If this is wrong, everything above cracks.
  2. World Model \u2014 spaces + environment, portal travel, acoustics, weather, items, containers, vitals. The physical reality the fiction must obey.
  3. Character \u2014 SPECIAL, skills, traits, appearance, perks, conditions, progression, relics.
  4. Social \u2014 NPC schema, appraisal, bonds, faction reputation, witness, gossip diffusion, benefit gating, liveness. The thirteen, reacting.
  5. Quest & Emergence \u2014 problems, discovery, the grounded generator, arbitration, encounters.
  6. Canon & Integrity \u2014 canon, severance, dm_context, backlog.
  7. AI Dungeon Master \u2014 snapshot, contract, bridge, effect filter, canon guard, lore DB + injection, the authoring pipeline.
  8. Content & Authoring \u2014 content-as-data packs. Definition of done: the town authored as pure data, zero engine code per NPC.
  9. UI \u2014 the Pip-Boy.

The rule of the stack: a layer may only depend downward. The DM reads the spine; the spine never calls the DM. Content is data the spine loads; content never contains logic.

2The Engine / DM Boundary \u2014 As Law

This is the line that keeps a weak local model viable and the world consistent. It is Article II made concrete. The DM sees only what the engine shows it, and may only return three kinds of thing:

  • Narration \u2014 prose. Free. Constrained only by canon and never-rules in context.
  • Classification \u2014 labels the engine asked for. "Doc's mood: offended." The engine converts the label to a number.
  • Proposal \u2014 a request to author content (a quest, an assembled area, a reaction). Goes to the validator, never straight to state.
\u2460 THE CONTROL LOOP
STATE \u2192 snapshot \u2192 Ollama DM \u2192 {narration, classifications, proposals} \u2192 validator + filter \u2192 effects \u2192 applyEffect \u2192 STATE

The model proposes; the engine disposes. Every number the player ever sees was set by deterministic engine code. The model's only power over mechanics is to suggest, and every suggestion is checked. This is why genocide can't accidentally raise Doc's regard: the model never had the pen.

3The Grounded Generator (working name: Relic Quests)

This is the gem \u2014 the reason the project exists. An intelligence that, reading the live world and grounded in lore, proposes quests, rewards, and small areas that make sense, assembled from assets that already exist. Option B from the grilling, specified.

It generates FROM state, not FOR scenarios

There is no script anticipating what the player might do. The generator reads whatever world exists right now \u2014 the cast still alive, the problems detected, the assets present \u2014 and proposes from that. This is precisely why it can "account for anything": there is always a state to read, even a catastrophic one. It never needs a pre-written branch, because it writes the branch from the room it is standing in.

The propose-and-validate pipeline

  1. Gather \u2014 the engine assembles grounded context: live problems, present cast, available assets, lore cards (3\u20136 keyword-matched), world bounds, the relic cooldown window.
  2. Propose \u2014 the intelligence returns a structured proposal: {giver, premise, objective, reward, assets[]}. It may only name assets that exist.
  3. Validate \u2014 every gate must pass, or the proposal dies silently:
    • Schema \u2014 well-formed; every referenced id resolves. No invented assets.
    • Canon Guard \u2014 violates no never-rule, contradicts no HARD canon entry.
    • Lore \u2014 grounded in the lore DB; the premise and entities are valid New Vegas.
    • Bounds \u2014 reward within caps (+5 skill / +120 XP); coordinates in-world; Reservation guard (no trespass on canon-reserved objective space).
    • Reconciliation \u2014 reads live state; never re-resolves what's already done (no fighting the same geckos twice).
  4. Commit \u2014 an accepted proposal is lowered to a concrete sequence of effects and dynamic-content nodes, applied through applyEffect, and logged. The instant it commits, it is data. The model is out of the loop.
Why this is the god-killer

The generator is a brilliant improv actor who knows every rule and only touches props that are real and on the stage. It is powerful but it cannot invent from nothing, cannot contradict the record, cannot exceed its budget. That constraint is not a weakness \u2014 it is the only thing that keeps the world consistent across infinite player choices. Remove the validator and you have the god, and the god forgets and contradicts itself within an hour. That is the tofu-dreg. The validator is load-bearing.

4The Frozen State Schema

One shape, versioned, frozen. The end of V15-vs-V19 drift. Content (authored definitions) lives in the registry and ships in packs; state (everything mutable) lives in the tree and is saved. AI-authored nodes land in state.dynamicContent so they save and replay like everything else.

// \u2500\u2500 SAVE FILE \u2014 the unit of truth on disk \u2500\u2500
SaveFile {
  schemaVersion: "20.0"      // bumps only on a breaking change
  contentPackVersion: string   // which authored packs to load
  seed: uint64                 // the world seed; all RNG derives from it
  savedAt: ISO8601             // metadata only \u2014 never read by logic
  state: State
  effectLog: EffectLogEntry[]  // ordered, since checkpoint
}

// \u2500\u2500 STATE \u2014 the single source of truth \u2500\u2500
State {
  meta:    { schemaVersion, turn:uint }
  rng:     { seed:uint64, cursor:uint }        // seeded PRNG position
  world:   { day, minute:0..1439, weather, sky, hazard }
  player:  PlayerState
  npcs:    { [npcId]: NpcState }
  factions:{ [factionId]: { standing:-100..100, state } }
  spaces:  { [spaceId]: { status, envOverrides, searched } }
  containers: { [id]: ContainerState }
  problems:   { [id]: Problem }
  relicQuest: { lastIssuedDay, active, issued[] }
  severed: { [nodeId]: { turn, reason } }
  dynamicContent: { spaces:{}, npcs:{}, items:{} }  // AI-authored, committed
  flags:   { [key]: value }
}

// \u2500\u2500 PLAYER \u2500\u2500
PlayerState {
  identity: { name, race, look, build, age }
  body:     { hp, maxhp, rads }
  needs:    { hunger, thirst, fatigue, heat, cold }   // 0..100
  wallet:   { caps }
  progress: { level, xp, xpToNext }
  baseSpecial: { STR,PER,END,CHA,INT,AGI,LCK }        // 1..10
  skills:   { [skill]: 0..100 }
  traits: [id]   appearanceTraits: [id]   perks: [id]   relics: [{id,name}]
  conditions: { [name]: { skillMods, specialMods, expiresTurn? } }
  tempSkills: { [skill]: { delta, expiresDay } }
  equipped:   { weapon:itemId|null, armor:itemId|null }
  inventory:  { [itemId]: qty }
  reputation: { [townId]: { fame:0..100, infamy:0..100, rumors:[] } }
  knownProblems: { [problemId]: { via, how, day } }
}

// \u2500\u2500 NPC \u2014 static DEF (authored, in pack) vs STATE (runtime, saved) \u2500\u2500
NpcDef {                // personality is AUTHORED, not simulated from nothing
  id, name, role, age, special:{S,P,E,C,I,A,L}

  essential:bool        houseControlled:bool        home:spaceId

  dm_context: { always, conditional[], never[] }
}
NpcState {
  regard:-100..100   mood:string   location:spaceId   alive:bool
  needs:{...}
  memory:{ durable:[{tag,note,turn}], transient:[...] }
  knowledge:[problemId]
}

// \u2500\u2500 SPACE \u2014 DEF (authored) vs STATE (runtime) \u2500\u2500
SpaceDef {
  id, name, region
  mapRect:[x,y,w,h]               // schematic floor-plan (UI) \u2014 AUTHORED
  origin3d:[x,y,z], size3d:[w,d,h] // metres, for ACOUSTICS ONLY
  env:{ brightness, temperature, shelter, noise, rads }
  dm_context:{ always, conditional[], never[] }
}

// \u2500\u2500 EFFECT \u2014 the atom of change. The ONLY thing that mutates State. \u2500\u2500
Effect { type:string, ...fields }   // validated vs the effect registry
EffectLogEntry { turn, effect, source:"engine"|"dm"|"player"|"system" }

// \u2500\u2500 CANON \u2014 write-only history \u2500\u2500
CanonEntry { id, lock:"HARD", kind, retell, turn }
The mapRect decision, locked

A space carries two geometries and they are not the same thing. origin3d/size3d are metres, for the acoustic solver only. mapRect is an authored schematic floor-plan for the UI. The V19 map looked wrong because it drew the schematic from the acoustic coords. Never again: the floor-plan is authored, never derived.

5The Relationship Model (locked)

Three axes, all signed -100..+100. This is frozen \u2014 the social web stands on it.

  • Regard \u2014 per-NPC, how one character feels about you. NpcState.regard.
  • Reputation \u2014 per-town Fame and Infamy (each 0..100), combined into a standing. How the place sees you.
  • Faction Standing \u2014 signed, per faction. state.factions[id].standing.

6Save & Replay \u2014 The Paradox, Dissolved

The hard question: how can a save replay if an AI keeps adding things to the world? The answer is the spine's cleverest move, and it is simple once seen:

The AI never enters the replay loop.
You replay its commits, not its authorship.

When the generator authors something, the result is frozen into concrete effects and dynamic-content nodes the instant it commits \u2014 checked against canon, then written to state and the log. From that moment it is data, exactly like a hand-authored asset. It is not "a thing the model did that we'd have to ask it to do again." It is a commit.

So a save is three things:

  1. the seed,
  2. a state checkpoint,
  3. the ordered effect log since that checkpoint \u2014 which already contains every AI-authored effect, now concrete.
REPLAY = load packs @version \u2192 restore checkpoint \u2192 re-run effect log against the seeded engine. The model is never re-prompted.

The model is nondeterministic; its artifacts are not, because they were logged. That is the whole trick.

The Determinism Tax \u2014 non-negotiable

This only holds if the engine is bit-for-bit deterministic. The price, as hard rules: every random call draws from state.rng (seeded), never Math.random(). Iteration over objects uses fixed, sorted key order. No Date.now() or wall-clock anywhere in logic. Float determinism watched (the Float32/Float64 class of bug that has bitten us before). Pay this tax and saves replay forever \u2014 even saves full of AI-authored content. Skip it and the dream is a lie.

7Severance = Consequence (the nuke, walked through)

"Account for any choice, even genocide" is answered not by a creative god but by the severance protocol producing a remembered wasteland. Here is exactly what happens when the player wipes out Goodsprings:

  1. 13 severances cascade. Each NPC is severed, not deleted: alive=false, a HARD canon entry written ("\u2026killed in the destruction of Goodsprings, day N"), every inbound bond flagged severed, grief propagation firing where bond strength > 50 \u2014 though here the mourners die too, so grief mostly writes epitaphs.
  2. The social web collapses node by node, each collapse logged. Faction ties drop to historical; reputation is preserved, not erased \u2014 your Infamy maxes.
  3. dm_context prohibitions auto-inject on every severed node: "narrate in past tense only; do not present as alive." The DM is now structurally unable to pretend the town lives.
  4. The result is a documented wasteland with a history. The engine did not break. It produced a valid, consequential, remembered state.
  5. The generator reads the ruins. The cast is now "Powder Gangers picking the bones, a survivor in the hills" \u2014 and it proposes, if anything, from that sparse vocabulary. Sparse cast \u2192 sparse proposals \u2192 desolation. Correctly.
A dead town is the right answer

"Account for any choice" does not mean "every choice spawns a mission." Manufacturing a chirpy questline out of the ashes to keep the player entertained would be less Fallout, not more. New Vegas itself answers genocide with a graveyard and a reputation, not a catering service. The honest outcome \u2014 a remembered wasteland that knows what you did \u2014 is the faithful one, and severance gives it to you for free. This is Article IV in the flesh.

9The Canonical Build Order

Each step stands on the one below. The gem comes last because it needs all of it underneath. Build in any other order and you are faking the headline again.

  1. Collapse to one engine, freeze this schema. Kill V16\u2013V19.1 as living lines. One spine; branch only content, never the engine. This ends the mess. \u2190 you are here
  2. Seeded PRNG + effect-log saves. The determinism tax, paid. This is what makes "the AI adds things AND saves replay" true instead of a contradiction. Nothing authored can be trusted before this exists.
  3. The living town. The 13 as schema, gossip diffusion, real liveness (schedules, goals, off-screen ticks). This is the simulation you actually want \u2014 the thing that reacts to anything.
  4. Harden the generator. Lore inputs, asset-assembly, the canon guard, the full validate-and-commit pipeline. The gem, on a spine that can hold it.
  5. Combat. Last. A whole subsystem, deferred by your own decision, and nothing above depends on it.

Why this order, in one line each: you can't trust authored content until saves are deterministic (1\u21922); the generator has nothing to read until the town lives (3 before 4); the gem needs lore + canon-guard + content-schema all present (4 needs 1\u20133); combat touches none of it (5 is independent and therefore last).

10What This Document Deliberately Leaves Open

A foundation says what is settled and what is not, so the boundaries are honest:

  • Combat depth and model \u2014 turn-based vs real-time vs narrative-dice. Deferred. Decided when step 5 arrives, not before.
  • The lore DB's source and shape \u2014 how the NV corpus is structured and ingested. Specced at step 4.
  • 2D / 3D presentation \u2014 a fidelity question above this spine. The state tree is renderer-agnostic by design; a 3D client reads the same truth.
  • The exact thirteen \u2014 the roster above is a proposal. Settle the cast.
  • Liveness depth \u2014 full off-screen simulation vs scheduled routines vs lazy-on-visit. The spine supports any; pick the ambition at step 3.
